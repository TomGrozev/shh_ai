# Conventions

ShhAi-specific rules — how this codebase does things that aren't obvious from the language or the stack packs. Domain vocabulary lives in `CONTEXT.md`; generic Elixir/Phoenix rules live in `rule://stack-elixir` and `rule://stack-phoenix`.

## Data access

- Route every DB read through `ShhAi.Audit.Queries`; never inline Ecto in a caller.
- Route every DB write through the `ShhAi.Audit.Writer` GenServer as a fire-and-forget cast; tests drain it with `Writer.call(:sync)`, never sleeps.
- Migrations: one `def change`, `create table(..., primary_key: false)`, explicit primary keys and indexes, no `timestamps()`.
- Ecto schemas declare an explicit `@primary_key`, use intent-named changesets (`insert_changeset`, `mapping_changeset`, …), and omit autogenerated ids and `timestamps()`.

## Configuration

- Read app config only through `ShhAi.Config` getters backed by `:persistent_term`; `Config.load/0` runs once at boot.
- In tests, mutate env as `put_env → Config.load() → assert`, restoring through `AuditCase.snapshot_env/1`.

## Errors and logging

- Store reads return `{:ok, _} | {:error, :not_found}`; writes return `:ok | {:error, term()}`.
- Fire-and-forget GenServer work rescues, logs, and degrades to a safe value — it never crashes the process.
- Error logs read exactly `Logger.error("<Module> <action> failed: #{inspect(reason)}")`; `Logger.metadata` stays unused.

## Tests

- Gate a heavy suite with `@moduletag`, exclude it in `test_helper.exs`, and give it a `mix test.<suite>` alias.
- Mock I/O at the seam: swap the HTTP transport through the `:http_client` app env, and stub a module with `:meck.new(mod, [:passthrough])` plus an `on_exit` unload.
